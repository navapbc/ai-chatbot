# GSN Eve/Jev preparation bridge

This dev-only service prepares explicitly supplied fictional Navoria section answers. It runs a separate Eve agent with the existing Vertex model identity and TypeSafe/Jev integration. The ordinary Riverside agent, browser tools and UI routes remain separate.

POST /api/gsn/prepare accepts only Ed25519 signed requests from GSN. The signature binds method, fixed path, timestamp, nonce and exact body. The public key is a deployment variable; no GSN resident token is accepted or forwarded. A shared-database primary key claims each request ID once across instances, preventing replay from starting another model run. Preparation is not an application mutation; a failed or uncertain service request must not be blindly replayed.

The isolated agent on loopback port 4275 requires an internal process secret. Its source is gsn-runtime/agent. Shell, file, web and delegation tools are disabled. Its single authored review_section tool returns only the supplied answers plus a fixed-question, annotate-only Jev response and usage. It has no application API, credentials tool, browser, signature, submission, or eligibility-decision capability. The route returns the actual Eve session ID and tool result; GSN verifies exact answer equality before applying its own authorization, schema and version checks. Failed Jev calls fail this optional combined path rather than claiming it was live.

The runtime inherits the existing provider configuration without copying provider credentials. Its PostgreSQL queue namespace and job prefix are isolated from the Riverside agent. The supervisor treats loss of any enabled runtime as a failed container. The image builds both Eve bundles; source-host build artifacts and workflow state are excluded. Only dev enables GSN_BRIDGE_PUBLIC_KEY; previews and prod remain disabled. Clearing the variable disables the bridge. Migration 0012 is additive and stores only consumed request IDs and timestamps. A shared database lock caps preparation at 100 requests per UTC day and four active runs, with four-minute crash leases; each Eve session also has input/output token limits.

Checks: bridge signature tests, restricted Eve bundle build, repository checks and a real model/TypeSafe preparation through the public GSN MCP are required. A mocked service response only tests the adapter contract and is not evidence of a live backend.
